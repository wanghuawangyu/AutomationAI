# 子文档五：Job

## 一、定位

Job 把 OP 或 Workflow **实例化为可执行作业**，绑定工作区，配置触发方式。

- 引用一个 OP 或一个 Workflow。
- 绑定工作区。
- 配置触发方式（手动 / 定时）。
- 配置并发策略、超时。
- 每次触发产生一个 Run。

## 二、数据结构

```typescript
interface JobDefinition {
  id: string;
  name: string;
  description?: string;

  // 作业目标
  target:
    | { kind: "op"; opId: string }
    | { kind: "workflow"; workflowId: string };

  // 工作区
  workspace: string;

  // 初始入参
  inputs: Record<string, unknown>;

  // 触发方式
  trigger:
    | { kind: "manual" }
    | { kind: "schedule"; cron: string; enabled: boolean };

  // 运行策略
  concurrency: "skip" | "queue" | "parallel";
  timeout?: number;

  createdAt: string;
  updatedAt: string;
}
```

## 三、字段说明

| 字段 | 说明 |
|-|-|
| id | 唯一标识 |
| name | 显示名称 |
| description | 描述 |
| target | 引用一个 OP 或一个 Workflow |
| workspace | 绑定的工作区路径 |
| inputs | 初始入参 |
| trigger | 触发方式 |
| concurrency | 并发策略 |
| timeout | 超时（秒） |

## 四、目标类型

| target.kind | 说明 |
|-|-|
| op | 引用单个 OP |
| workflow | 引用整个 Workflow |

## 五、Job 交互性

| Job 的 target | 交互性来源 |
|-|-|
| `{ kind: "op", opId }` | 该 OP 的 interactive 属性 |
| `{ kind: "workflow", workflowId }` | 该 Workflow 的交互性 |

**执行位置约束**：

| 类型 | 能否在 Job 界面直接运行 | 执行位置 |
|-|-|-|
| 非交互式 OP / Workflow / Job | ✅ 可以 | Job 界面触发，创建后台 Run |
| 交互式 OP / Workflow / Job | ❌ 不可以 | 必须在工作台中触发（人工推进） |

**理由**：交互式任务需要用户随时介入（打开终端、人工确认）。Job 界面是配置管理界面，不是交互界面。

## 六、触发方式

| 触发方式 | 说明 | 适用 |
|-|-|-|
| 手动 | 用户在 UI 点击"运行" | 所有非交互 Job |
| 定时 | Cron 表达式，后台调度 | 非交互 Job |

### 6.1 手动触发

- 用户点击"运行"按钮。
- 引擎创建 Run，使用 Job 绑定的工作区和初始入参。
- Run 进入后台执行。

### 6.2 定时触发

- 通过 Cron 表达式配置。
- 引擎按 Cron 调度，创建 Run。
- 交互式 Job 禁止定时触发（校验时报错）。

**定时触发限制**：

| 限制 | 说明 |
|-|-|
| 交互式 Job 禁止定时 | 校验时报错 |
| 上一次未完成 | 按 concurrency 策略处理 |
| 应用未运行 | 错过的触发不补（或按配置补） |

## 七、并发策略

| 策略 | 说明 |
|-|-|
| skip | 若上一个 Run 未完成，跳过本次触发 |
| queue | 排队等待，前一个完成后执行 |
| parallel | 并行执行，允许多个 Run 同时存在 |

## 八、Job 管理器

### 8.1 列表视图

```text
┌──────────────────────────────────────────────────────────┐
│  作业管理                              [＋ 新建]          │
├──────────────────────────────────────────────────────────┤
│  🔍 搜索...                                              │
├──────────────────────────────────────────────────────────┤
│  ⏰ daily_cleanup    OP: clean_logs     非交互  0 2 * * *  ✅ 启用  [运行] [编辑] [禁用] [删除] │
│  ⏰ hourly_check     Workflow: health   交互式  0 * * * *  ✅ 启用  [运行置灰] [编辑] [禁用] [删除] │
│  📌 manual_deploy    Workflow: deploy   非交互  手动       —      [运行] [编辑] [删除] │
└──────────────────────────────────────────────────────────┘
```

- **非交互** Job 的"运行"按钮可点击。
- **交互式** Job 的"运行"按钮置灰，悬停提示"交互式作业，请在会话中触发"。

### 8.2 编辑器视图

```text
┌──────────────────────────────────────────────┐
│  ← 返回  编辑: hourly_check                   │
├──────────────────────────────────────────────┤
│  名称: [hourly_check         ]                │
│  描述: [每小时健康检查        ]                │
│                                              │
│  目标类型:                                    │
│  ● 单个 OP                                    │
│    OP: [health_check ▾]                      │
│  ○ 整个 Workflow                              │
│    Workflow: [选择 ▾]                         │
│                                              │
│  工作区: [/path/to/workspace]                 │
│                                              │
│  初始入参:                                    │
│    endpoint: [https://api.internal/health ]  │
│                                              │
│  触发方式:                                    │
│  ● 手动 + 定时                                │
│    Cron: [0 * * * *        ]                 │
│    启用: [✓]                                  │
│  ○ 仅手动                                     │
│                                              │
│  交互性: ⚠ 交互式（target 包含交互式 OP）      │
│  提示: 交互式作业无法在 Job 界面直接运行       │
│                                              │
│  并发策略: [skip ▾]                           │
│  超时: [300s]                                 │
│                                              │
│           [取消]  [保存]  [试运行]            │
└──────────────────────────────────────────────┘
```

### 8.3 编辑器交互规则

| 情况 | 行为 |
|-|-|
| target 为非交互 OP / Workflow | "运行"按钮可点击 |
| target 为交互式 OP / Workflow | "运行"按钮置灰，提示需在会话中触发 |
| 定时触发 + 交互式 | 校验不通过，禁止保存 |
| 试运行 | 只有非交互 Job 可试运行 |

## 九、Job 执行流程

```text
┌──────────────────────────────────────────┐
│  1. 触发（手动 / 定时）                    │
└─────────────────┬────────────────────────┘
                  ▼
┌──────────────────────────────────────────┐
│  2. 检查交互性                            │
│     - 交互式 Job 拒绝在 Job 界面运行       │
└─────────────────┬────────────────────────┘
                  ▼
┌──────────────────────────────────────────┐
│  3. 检查并发策略                          │
│     - skip / queue / parallel             │
└─────────────────┬────────────────────────┘
                  ▼
┌──────────────────────────────────────────┐
│  4. 创建 Run                              │
│     - 使用 Job 的 workspace 和 inputs      │
│     - 记录 triggeredBy                    │
└─────────────────┬────────────────────────┘
                  ▼
┌──────────────────────────────────────────┐
│  5. 提交给执行引擎                         │
│     - 执行 OP 或 Workflow                 │
└─────────────────┬────────────────────────┘
                  ▼
┌──────────────────────────────────────────┐
│  6. Run 状态写入运行历史                   │
└──────────────────────────────────────────┘
```

## 十、Job 与 OP / Workflow / Run 的关系

| 关系 | 说明 |
|-|-|
| OP → Job | Job 可以引用单个 OP 作为 target |
| Workflow → Job | Job 可以引用整个 Workflow 作为 target |
| Job → Run | 每次触发产生一个 Run |
| 修改影响 | Job 修改只影响自身，不影响 OP / Workflow |

## 十一、Job 交互性传播链

```text
OP.interactive
    ↓ 传播
Workflow.interactive = 引用的 OP 中任意一个 interactive
    ↓ 传播
Job.interactive = target 的 interactive
```

## 十二、两种执行来源

```text
┌────────────────────────────────────────────────────────────┐
│  执行来源 A：Job 管理界面                                    │
│  - 只能执行非交互式 Job                                      │
│  - 使用 Job 自身绑定的工作区                                  │
│  - 创建一个后台 Run                                          │
│  - 执行历史只能在运行历史界面查看                              │
└────────────────────────────────────────────────────────────┘

┌────────────────────────────────────────────────────────────┐
│  执行来源 B：工作台中触发                                    │
│  - 可以执行交互式或非交互式任务                               │
│  - 继承当前工作区                                             │
│  - 非交互任务可直接后台执行                                   │
│  - 交互任务需人工推进                                         │
│  - 执行历史可以在运行列表查看，也可在运行历史查看              │
└────────────────────────────────────────────────────────────┘
```

## 十三、执行记录

| 执行来源 | 运行列表的可见性 | 运行历史的可见性 |
|-|-|-|
| Job 界面触发 | ❌ 不在运行列表中显示 | ✅ 在运行历史可见 |
| 工作台中触发 | ✅ 在运行列表可见 | ✅ 在运行历史可见 |

## 十四、关键设计决策

| 决策点 | 建议 | 理由 |
|-|-|-|
| 定位 | 可执行的作业配置 | 与 OP / Workflow 分层清晰 |
| 目标 | 引用 OP 或 Workflow | 灵活复用 |
| 触发方式 | 手动 / 定时 | 覆盖主要场景 |
| 交互性 | 动态计算（target 的交互性） | 自动传播 |
| 执行位置 | 交互式必须在工作台触发 | 需要稳定的交互界面 |
| 并发策略 | skip / queue / parallel | 灵活控制 |
| 存储 | 本地 SQLite | 轻量、事务性 |
