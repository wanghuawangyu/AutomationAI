## 严重

### S-1【严重】唯一权威文件 `_fix_v4_decisions.md` 的分区**算式不成立**，且与 `crud-03` 落地相反

**位置与原文**（`_fix_v4_decisions.md:36`，§二.6 拍板 6）：
> 现「A 4 + B 10 = 14」与「共 16 条」矛盾；改为 A `9/10/11/16` + B `1–8/13–15/18` + C `12/17` = **17 条**，逐条列出后计数自证。

**实测**：A `9/10/11/16` = 4；B `1–8/13–15/18` = 8+3+1 = **12**；C `12/17` = 2 → **4+12+2 = 18 ≠ 17**。而 `crud-03:108/111-115` 实际落地为 **B = `1–7/13–15/18`（11 条）**，并写明「D2 原文的『1–8』含本轮已删除的原第 8 条『汇聚』，故实为 1–7」——即 `crud-03` **正确地偏离了本文件**。

**问题**：① 本文件被 `validation.md:6` 及自身 `:3` 定为**唯一权威**（「与报告冲突以本文件为准」）；② 其算式自身不成立；③ 按本文件的字面分区（B 含 8）核对 `crud-03`，会判「`crud-03` 漏了第 8 条」——而第 8 条正是本轮**明令删除**的「汇聚」（`:149`）。同一事实在「权威文件 / 契约基准」两处相反，且这是**计数类**缺陷（历轮单一缺陷模式）。

**建议改法**：`_fix_v4_decisions.md:36` 改为「A `9/10/11/16`（4）＋ B `1–7/13–15/18`（11）＋ C `12/17`（2）= **17 条**，编号 8 留空（原第 8 条『汇聚』已删除）」——与 `crud-03:108/115/149`、`p01:1356`、`tasks:230` **逐字一致**。**历史 `_fix_v*` 报告不改**，但须在本报告留档为「口径源自相矛盾」。
