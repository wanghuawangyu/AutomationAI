### D6 边状态推演（文字表格化）

**统一记号**：边状态 ∈ `pending / activated / dropped`；前缀节点集 = 种子节点 + 其**全部前置**；`skipped 传播` = 节点入边全 `dropped` → 其出边全 `dropped`（`crud-03:807`）。

**例 A（文档自带，`crud-03:1294`）**：`Start→A`、`A→{on_success}B`、`A→{on_success}End`、`B→{on_success}End`；源 Run：A 成功、B 失败（无失败出边 → `run_failed`）→ 终态 `failed`。

| 边 | 源 Run 终态 | 新 Run 初值（① 种子入边 / ② 前缀出边复制） | B 完成后（walk_edge 重判） |
|-|-|-|-|
| `Start→A` | activated | activated（②，Start 属前缀） | — |
| `A→B` | activated | activated（① + ②） | — |
| `A→End` | activated | **activated（② 的关键作用；不复制则永停 `pending`）** | activated |
| `B→End` | dropped | dropped（②，种子属前缀；随后被 B 的 walk_edge 覆盖） | B 成功 → **activated** |
| End 判定 | — | 入边 = {activated, dropped} 已全决定且有 activated，但种子在飞 → 不收敛 | 入边 = {activated, activated} → **End 到达 → success** ✓ |

→ **防住**。文档 ④ 的风险句（不复制则 `A→End` 永 `pending` → End 永久挂起候选）**判断正确**。

**例 B（本轮构造：菱形 + 回跳，题目要求）**：`Start→A`；`A→{on_success}B`；`A→{on_success}End`；`B→{on_success}C`；`C→{on_failure}B`（回跳边）；`C→{on_success}End`。（End 为 join，`A→End` 与 `C→End` 两条入边；`B` 有入边 `C→B` 回跳。）源 Run：A ✅ → B(act1) ✅ → C(act1) ❌ → `C→B` activated → B(act2) ✅ → C(act2) ❌ → … 触及 `min(max×3, max_loop_multiplier)` → `terminate(loop_limit)` → 终态 `failed`。取 C 的**最后一条失败记录**为种子（`crud-03:1278` / `crud-05:392`）。

| 边 | 源 Run 终态 | 新 Run 初值 | 推演结果 |
|-|-|-|-|
| `Start→A` | activated | activated（②） | — |
| `A→B` | activated | activated（②） | — |
| `A→End` | activated | **activated（②）** | join 的第 1 条入边已定 ✓ |
| `B→C` | activated | activated（① 种子入边 + ②） | 起点就绪不要求入边激活（`:1297`）✓ |
| `C→B` | activated（on_failure 命中） | **activated（② 复制）**；B 属前缀且 `completedOnce=true`（③）→ 该边在 C 完成时被判定为**回跳边**，B 以 `activation_seq+1` 重入 | 与 4.3.0③ 一致，不产生死锁 |
| `C→End` | dropped（on_success 未命中） | dropped（②） | C 重跑后由其 walk_edge 重判 |
| **分支 1：C 成功** | — | — | `C→End` → activated；End 入边 = {`A→End` activated, `C→End` activated} → **End 到达 → success** ✓（B 未被误重入） |
| **分支 2：C 再次失败** | — | — | `C→B` activated → B 为已执行过节点 → 回跳重入 B（`activation_seq+1`）→ 循环按上限终止 → `failed` ✓（无限循环被 `min(max×3, max_loop_multiplier)` 兜住） |

→ **防住**；菱形 + 回跳在「② 只复制前缀出边 + ③ `completedOnce`」下不卡死。

**例 C（本轮反例：死枝喂 join）**：`Start→A`；`A→{on_success}B`；`A→{on_failure}Z`；`B→{on_success}End`；`Z→{on_success}End`（合法性：规则 1–7 全通，无环）。源 Run：A ✅ → `A→B` activated、`A→Z` **dropped** → Z 入边全决定且无 activated → **Z skipped → `Z→End` dropped**（skipped 传播）；B 执行 → B ❌（无失败出边）→ `run_failed` → 终态 `failed`。种子 = B 的失败记录。

| 边 | 源 Run 终态 | 新 Run 初值 | 是否被规则覆盖 |
|-|-|-|-|
| `Start→A` | activated | activated | ② ✓ |
| `A→B` | activated | activated | ① + ② ✓ |
| `A→Z` | dropped | dropped | ② ✓ |
| `B→End` | dropped | dropped（种子出边，稍后被 walk_edge 覆盖） | ② ✓ |
| **`Z→End`** | dropped | **pending** | **无任何规则覆盖**（Z 既不在前缀节点集，也不从种子 B 正向可达） ✗ |

推演：init → dispatch B（种子）→ B 成功 → `walk_edge(B)` → `B→End` = **activated** → 对 End 求值：入边 = {`Z→End` **pending**, `B→End` activated} → **不满足「所有入边均已决定」** → End 记入**挂起候选**（`:810`：已由 walk_edge 评估但入边未全决定）→ 无在飞步骤、无 `pending_reentry` → **收敛永不成立 → `job_runs.status` 永久 `running`**（与 D6 想要消除的故障同族）。

→ **未防住**：② 的复制范围只覆盖「前缀节点集的**出**边」，没有处理「源 Run 中已 skipped 的旁支节点的出边」，而这类边正是 join 的其余入边。（`crud-05:394` 同缺。）

### S1【严重】D6 边状态初值漏「死枝闭包」→ 旁支入边永久 `pending`、Run 卡死

- 位置：`proposal-02-后端crud-03workflow管理.md:1290-1295`（4.3.4②，镜像处 `proposal-02-后端crud-05运行历史.md:394`）
- 原文（`crud-03:1292`）：`> - ② **前缀节点集的出边按其源 Run 终态边状态复制**（源 Run 中已 `activated` 的保持 `activated`、已 `dropped` 的保持 `dropped`，**不得重置为 `pending`**）；`
  原文（`crud-03:1294`）：`④ **风险说明**：若不复制前缀边状态，菱形 / 并行汇聚结构会卡死——如 Start → A、A →{on_success} B、A →{on_success} End、B →{on_success} End（源 Run 中 A 成功、B 失败），重试从 B 起跑时 A→End 这条入边会**永远停在 pending**…`
- 问题：规则 ①②③ 只保证「**种子节点入边**」与「**前缀节点出边**」被决定；join 节点的其余入边若来自**源 Run 中被 skipped 的旁支**（`Z`），在新 Run 中既不会被复制、也不会被任何 walk_edge 重新评估（Z 永不执行）→ 永久 `pending` → 收敛判定永不成立（推演例 C）。这与 4.3.4② 自称要消除的「永久 pending → Run 卡死」是同一故障族，属**修复未闭环**。
- 建议改法（最小增补，两文件同一句）：在 `crud-03:1293` 与 `crud-05:394` 的 ③ 之后各增一条：
  > ⑥ **死枝闭包（必做）**：源 Run 终态中**入边已全部决定且无 activated**（即被 `skipped` / 不可达）**且既不属于前缀节点集、也不从种子节点正向可达**的节点，其**出边一律置 `dropped`**，并递归传播至不动点后再 dispatch 种子。否则这类旁支的入边会在 join 处永久 `pending`——例：`Start→A`、`A→{on_success}B`、`A→{on_failure}Z`、`B→End`、`Z→End`（源 Run 中 A 成功、B 失败 → Z 被 skipped），重试从 B 起跑后 `Z→End` 永为 `pending` → End 永久**挂起候选** → Run 永久 `running`。
  等价且更稳妥的表述：**初始化 = 「全边 pending」→ 前缀出边复制 → 种子入边 activated → 跑一次 skipped 传播不动点 → dispatch 种子与已就绪节点**。
- 附：`tests/集成测试用例.md:1664-1672`（TC-X5e1a）的图为 `A→B→C` **线性**，不覆盖 join/旁支 → 该缺陷无验收用例（见 N5，建议补例）。
