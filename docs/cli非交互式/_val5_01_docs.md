- **缺口**：② 只复制「**前缀节点集**（种子 + 其全部前置节点）」的**出边**；④ 只处理「入边已决定且**无** activated」的节点。**中间类**——「既不在前缀集、也不从种子正向可达、且源 Run 中入边已决定**且有** activated」的节点——**既不被 ② 覆盖（其入边来源节点不在前缀集 → 入边不复制 → 新 Run 中仍 `pending`）、也不被 ④ 覆盖（有 activated → 非死枝）**。这类节点的入边在新 Run 中无人决定 → 其自身永不被 dispatch、其出边永不定 → 下游 join（如 End）永久 `pending` → 收敛永不成立。
- **最小反例（可复现推演）**：图 `Start →(always) A`、`Start →(always) X`、`A →(on_success) B`、`B →(on_success) End`、`X →(always) Y`、`Y →(always) End`。
  源 Run：A 成功 → B；B 失败（B 无 `always`/`on_failure` 出边 → 按 `crud-03:816` V11-B 置 `run_failed`、**不 abort 在飞**）；此时 X 仍在跑，X 完成后按 `crud-03:856`「置边状态**仍照常执行**…仅跳过…dispatch」→ `X→Y` 写为 `activated`，但 **Y 不 dispatch**（无 step_record）；随后收敛 → 源 Run `failed`。
  重试（种子 = B 失败记录）：前缀集 = {Start, A, B}（`crud-03:1292`）。① 全 `pending`；② 复制 Start/A/B 出边 → `S→X`=activated；③ B 入边 activated；④ 死枝闭包：**Y 的入边 `X→Y` 在源 Run 为 activated → Y 不属于死枝**（条件「无 `activated`」不满足），**X 同样非死枝** → **无人置 `X→Y`**；于是新 Run 中 `X→Y` 仍是 `pending` → Y 永不就绪（`:804` 要求所有入边已决定）→ `Y→End` 永不决定 → End 永不 ready → **Run 永久 `running`**。
  （若把 X/Y 换成「已完成」的节点，结论不变：只要该节点的**入边来源不在前缀集**，其入边就不被复制；只是入口形态不同。）
- **同类可达场景**：`cancelled` 且含失败/超时 step 的 Run（`crud-05:388` D15 声明**可重试**）——用户终止时另一并行分支的节点已 `activated` 但未执行/被置 `cancelled`，同样落入上述缺口；`timeout` 终止（`:1113` 不走任何边、整个 Run 终止）后，别支已 activated 的边亦同。
- **为什么这是新问题（而非第 4 轮 S1 的重复）**：第 4 轮 S1 = 「**skipped** 旁支入边永久 pending」，已按 ④ 修复（本轮实测已落地）；本条 = 「**activated** 旁支入边永久 pending」，④ 的判据 `无 activated` 恰好把它排除在外 → **同一故障族、修复未闭环**。
- **建议改法（择一，需拍板，见 P1）**：
  - **A（推荐，最小改动）**：② 的作用域从「前缀节点集的出边」改为「**源 Run 终态中全部已决定的边**」，随后**只把「将从种子起重新执行」的节点（种子 + 从其正向可达者）的出边重置为 `pending`**；④ 保留为幂等兜底（此时自然满足）。等价表述：`全边 pending →（整体复制源 Run 终态已决定边）→ 重置「种子∪种子正向可达」的出边为 pending → 种子入边 activated → 死枝/未定枝闭包至不动点 → dispatch`。
  - **B（补一条判据）**：④ 的判据放宽为「**入边已全部决定**且**不属于前缀节点集、也不从种子节点正向可达**」的节点，其**出边按其源 Run 终态复制**（activated 保 activated、dropped 保 dropped）；再对源 Run 中「入边**未**全决定」者一律置 `dropped`。
  - 两方案均需同步 `crud-03:843`（起点判定括注）与 `crud-05:395` 括注，并在 `tests` 增「并行分支 + 失败传播 + 重试」负向用例（现有 TC-X5e5 只覆盖「菱形 + 旁支 skipped」）。
