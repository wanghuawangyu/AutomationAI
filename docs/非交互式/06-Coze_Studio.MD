# Coze Studio 使用方式与场景分析

## 一、安装部署：唯一前置依赖是 Docker

Coze Studio 的本地部署流程非常直接，**Docker 是唯一的前置依赖**。

**硬件要求**（普通家用电脑即可满足）：
- CPU：2核或以上
- 内存：4GB 或以上
- 存储：至少 2GB 可用空间

**部署步骤**：
1. **安装 Docker Desktop**：从官网下载安装包，Windows 用户需启用 Hyper-V，安装完成后确认状态栏显示 "Running"。
2. **获取源码**：
   ```bash
   git clone https://github.com/coze-dev/coze-studio.git
   cd coze-studio/docker
   cp .env.example .env
   ```

3. **配置模型服务（关键步骤）**：进入 `backend/conf/model/` 目录，复制模板文件并填入你的 API Key。以 DeepSeek 为例：
   ```bash
   cp template/model_template_ark_volc_deepseek-r1.yaml deepseek-r1.yaml
   ```
   编辑该文件，设置 `base_url`、`api_key` 和 `model` 参数。
4. **一键启动**：在 `coze-studio/docker` 目录执行：
   ```bash
   docker compose --profile "*" up -d
   ```

5. **访问**：启动完成后，在浏览器中打开本地服务地址即可进入 Coze Studio 界面。

## 二、图形化编排：工作流与智能体

Coze Studio 提供**零代码或低代码**的可视化开发环境，核心操作在浏览器画布上通过拖拽完成。

**工作流编排**
工作流由多种节点组成，通过拖拽和连线构建自动化流程：

| 节点类型 | 作用 |
|:---|:---|
| **触发节点** | 工作流起点，支持手动、API、定时、Webhook 等方式 |
| **大模型节点** | 调用 LLM，可配置温度、最大令牌数等参数 |
| **代码节点** | 执行自定义代码逻辑 |
| **判断/选择器节点** | 实现条件分支，支持多条件嵌套 |
| **循环节点** | 支持数组循环、指定次数、无限循环 |
| **工具/插件节点** | 连接外部服务或插件 |
| **知识库检索节点** | 从知识库中检索内容（RAG） |

**智能体（Agent）构建**
创建 Agent 时，需要配置以下核心要素：
- **名称与描述**：建议带岗位前缀，方便识别
- **人设与回复逻辑**：编写 Prompt 定义 Agent 的行为方式
- **模型选择**：选择底层 LLM
- **技能配置**：添加插件、工作流、知识库等资源

Coze 还支持**多 Agent 协作模式**，允许为一个智能体添加多个独立 Agent 节点，通过节点连接实现任务分发与协作。

## 三、接入本地 Agent CLI（coze-bridge）

这是 Coze Studio 与你场景最相关的特性。它通过 **coze-bridge** 这个轻量程序，将你电脑上已安装的本地 Agent CLI 接入 Coze，**Agent 本身始终运行在你的电脑上，不会迁移到云端**。

**支持接入的本地 Agent**：Claude Code、Codex CLI、OpenClaw、Hermes。

**接入步骤**：
1. **确保本地已安装并登录**对应的 Agent CLI。
2. **在 Coze 页面获取连接命令**：进入"接入本地 Agent"界面，复制系统生成的命令，格式类似：
   ```
   npx -y coze-bridge@latest --pat-token=<你的token> --pair-code=<配对码>
   ```
3. **在本地终端执行该命令**，保持终端开启，等待出现 `coze-bridge:paired` 的回显。
4. 连接建立后，即可在 Coze 中与本地 Agent 对话，让它处理本机文件、代码等项目。

**技术原理**：coze-bridge 是一个本机后台 daemon，将 Coze 云端的 **Frontier 协议**翻译为本地 Agent 能理解的 **ACP（Agent Client Protocol）协议**，实现双向通信。

**重要注意事项**：
- 使用期间需**保持 coze-bridge 进程运行**，电脑关机、断网或休眠会导致连接断开。
- 本地终端对话与 Coze 中的对话**属于不同会话，内容不同步**。
- 接入需要 **Node.js ≥ 22**。

## 四、触发与运行方式

Coze 工作流支持多种触发方式，适合非交互式自动化场景：

| 触发方式 | 说明 |
|:---|:---|
| **手动触发** | 在界面中点击运行，适合调试 |
| **API 调用** | 通过 OpenAPI 从外部系统发起调用 |
| **Webhook** | 外部系统向指定 URL 发送 POST 请求触发 |
| **定时任务** | 通过 Cron 表达式配置周期执行，如 `0 8 * * *` 表示每日 8 点 |
| **事件驱动** | 由外部事件（如 Git 推送、新订单）触发 |

**配置方式**：在开始节点的右侧面板中切换至"触发器设置"，启用触发器并选择触发类型。

## 五、适合你的场景吗？

| 维度 | Coze Studio 的情况 |
|:---|:---|
| **部署方式** | 官方推荐 Docker 容器化部署，唯一前置依赖是 Docker |
| **本地 Agent 接入** | ✅ 原生支持，通过 coze-bridge 接入本地 CLI，Agent 在本地执行 |
| **权限继承** | 本地 Agent 以你当前用户身份运行，理论上可继承本地权限 |
| **桌面端** | ✅ 有（Mac/Windows），但主要作为连接本地文件的入口 |
| **编排能力** | ✅ 零代码拖拽，节点丰富，支持条件分支和循环 |
| **成熟度** | 源自服务了上万家企业、数百万开发者的扣子开发平台，开源版本已迭代至可稳定运行 |

**关键判断**：Coze Studio 的 **coze-bridge 机制确实能让你在本地 CLI 上执行任务并继承用户权限**，这与你手动在终端执行 Agent CLI 的上下文基本一致。但它的**官方部署方式仍然是 Docker**——虽然桌面端可以自动执行连接命令，但 Coze Studio 的核心服务（工作流编排引擎、模型管理等）仍运行在容器中。

如果你能接受 **Docker 作为基础运行环境**，同时希望获得**零代码的图形化编排体验**和**原生本地 Agent 接入能力**，Coze Studio 是一个非常值得考虑的选择。但如果你坚持**完全裸进程、无任何容器依赖**的部署方式，Langflow 桌面版仍然是更匹配的方案。
