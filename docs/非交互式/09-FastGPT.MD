# FastGPT 与 Langflow 对比及 FastGPT 详细介绍

## 一、FastGPT 和 Langflow 是同类产品吗？

**不是同类产品。**

FastGPT 是**面向知识库问答（RAG）的端到端 AI 应用平台**，核心强项在于知识库管理和高并发问答；而 Langflow 是**面向开发者的 LLM 逻辑可视化编排 IDE**，核心强项在于用拖拽方式精细控制 AI 链路的每一个环节。


## 二、FastGPT 详细介绍

### 核心定位：企业级 RAG 知识库问答与 AI Agent 构建平台

FastGPT 是一个基于大语言模型的 AI Agent 应用开发平台，由 labring 团队开发并维护，采用 Apache 2.0 协议开源。它的核心定位非常清晰：**以知识库问答为中心，提供从数据导入、知识结构化、检索增强生成（RAG）到智能问答的全流程自动化能力**。它被定位为“最轻量的 RAG+Agent 平台”，适合个人、小团队以及需要快速构建企业知识库问答系统的场景。

### 核心功能

| 功能模块 | 说明 |
|:---|:---|
| **全能知识库** | 支持导入 PDF、Word、Markdown、CSV、Excel 等多种格式，智能处理复杂文档结构（保留图片、表格、LaTeX 公式），自动识别扫描文件，并结构化为清晰的 Markdown 格式 |
| **可视化工作流** | 通过拖拽式画布搭建问答流程，支持知识库搜索、AI 对话、问题分类、条件判断、循环、并行执行、工具调用等节点 |
| **数据智能解析** | 全流程自动化：数据导入 → 预处理 → 知识匹配 → 智能问答 |
| **Agent 编排** | 支持 Agent 模式，内置虚拟机执行环境，可运行 Shell 脚本和代码 |
| **API 集成** | 完全对齐 OpenAI 官方接口格式，支持一键接入企业微信、公众号、飞书、钉钉等平台 |

### 技术栈与架构

FastGPT 采用 **Next.js + TypeScript** 作为前端，后端使用 **Node.js**，数据库采用 **MongoDB + PostgreSQL（pgvector 插件）或 Milvus**。代码执行节点由独立的 **fastgpt-sandbox** 沙盒服务托管，在安全沙盒中执行 JavaScript 和 Python 代码。

**GitHub Stars**：约 **29k+**（2026 年数据）

### 部署方式

FastGPT 的**官方推荐部署方式是 Docker Compose**，一键启动所有服务。也支持 **Sealos 云平台一键部署**（无需采购服务器，支持高并发和动态伸缩）。**没有官方桌面应用**，通过浏览器访问 UI（默认端口 3000）。

### 内网/离线支持

FastGPT **明确支持完全离线部署**，这是它的核心卖点之一。所有数据——模型权重、向量数据库、对话日志——均可存储于企业内网，敏感信息不会外泄。支持通过 **Ollama** 等本地模型推理框架接入本地 LLM，实现 100% 内网闭环。内置权限管理模块，可与 LDAP 或 OA 系统对接，实现部门级、项目级的数据隔离。

### 调用本地 CLI 的能力

FastGPT 的 **Agent 虚拟机（Agent V2）** 功能允许 Agent 调用代码执行器运行 Shell 脚本，在 `/workspace` 目录下进行文件读写操作，或通过配置的启动脚本完成环境初始化。**代码运行节点**支持在安全沙盒中执行 JavaScript 和 Python 代码，私有化用户需要部署 `fastgpt-sandbox` 镜像并配置 `CODE_SANDBOX_URL` 环境变量。

**关键限制**：代码在**独立沙盒服务**中执行，而非直接在 FastGPT 主进程的子进程中运行。这意味着 **CLI 调用继承的是沙盒服务的运行身份和环境**，而非你当前登录的桌面用户。如果你的内部 Agent CLI 的权限校验严格依赖“当前操作系统用户”，沙盒环境可能与手动执行的上下文不一致。

### 📊 FastGPT 与 Langflow 核心差异

| 维度 | **FastGPT** | **Langflow** |
| :--- | :--- | :--- |
| **核心定位** | 企业级 RAG 知识库问答平台 | LLM 逻辑可视化编排 IDE |
| **主要开发语言** | TypeScript / Node.js | Python |
| **强项** | **知识库管理、RAG 检索、高并发问答** | **LLM 链路精细编排、自定义 Python 组件** |
| **RAG 能力** | **极强**，内置完整知识库管道 | 节点式手动搭建，需自行配置 |
| **工作流节点** | 34 个预置节点（知识库搜索、AI 对话、条件判断等） | 基于 LangChain 的丰富组件库 |
| **自定义代码** | 沙盒执行 JS/Python，需部署 sandbox 服务 | 自定义 Python 组件，`subprocess` 直接可用 |
| **部署方式** | Docker Compose / Sealos | Docker / pip / **原生桌面应用** |
| **内网离线** | ✅ 完全支持，本地模型 + 内网闭环 | ✅ 桌面版自带依赖，无需联网 |
| **调用本地 CLI** | 沙盒环境，权限上下文与桌面用户**分离** | 自定义组件直接 `subprocess`，**继承桌面用户权限** |

### 💎 结合你内网办公场景的判断

| 维度 | **FastGPT** | **对你的意义** |
| :--- | :--- | :--- |
| **同类产品** | ❌ 与 Langflow 不同类 | 定位不同，FastGPT 以 RAG 知识库为核心，Langflow 以 LLM 逻辑编排为核心 |
| **内网离线** | ✅ 完全支持 | 适合内网 |
| **权限继承（CLI 调用）** | ⚠️ 沙盒环境，与桌面用户**分离** | **可能与权限校验要求不匹配** |
| **桌面应用** | ❌ 无 | 通过浏览器访问，需维护 Docker 服务 |
| **AI 能力重心** | RAG 知识库问答 | 非 CLI 编排工具 |

**结论**：FastGPT 是一款**优秀的 RAG 知识库问答平台**，如果你的核心需求是**构建企业知识库、实现智能问答和文档检索**，它是非常合适的选择。但就你“**在办公电脑上以裸进程直接调用带权限校验的内部 Agent CLI**”这一核心需求而言，FastGPT 存在一个**实质性障碍**：它的代码执行运行在**独立的沙盒服务**中，CLI 调用继承的是沙盒进程的身份和环境，而非你当前登录的桌面用户。如果你的内部 Agent CLI 的权限校验严格依赖“当前操作系统用户”，FastGPT 的沙盒机制可能导致校验失败。

**Langflow 桌面版仍然是更匹配你场景的方案**——它以单进程桌面应用运行，自定义 Python 组件中的 `subprocess` 调用直接继承你的桌面用户权限，路径最短、权限上下文最一致。
